# Todo List Web App 规格说明

## 为什么
需要一个可在浏览器中快速记录、整理与完成待办事项的轻量应用，并支持离线使用与跨刷新持久化。

## 变更内容
- 新增一个单页 Todo Web 应用：新增/编辑/完成/删除待办
- 支持筛选视图：全部/未完成/已完成
- 支持本地持久化：使用浏览器本地存储保存数据
- 支持基础可用性：键盘操作、清晰的交互反馈、响应式布局

## 影响
- 影响的能力：待办管理（CRUD）、状态筛选、本地存储持久化
- 影响的代码：待新建（前端工程、页面与组件、状态与存储层、测试）

## 新增需求

### 需求：待办管理
系统 SHALL 允许用户创建、查看、编辑、完成与删除待办事项。

#### 场景：创建待办成功
- **WHEN** 用户输入标题并提交
- **THEN** 新待办出现在列表顶部（或按创建时间排序），且标题与状态正确

#### 场景：编辑待办成功
- **WHEN** 用户对某条待办进入编辑并保存
- **THEN** 列表展示更新后的标题，且不改变其完成状态

#### 场景：完成/取消完成成功
- **WHEN** 用户切换某条待办的完成状态
- **THEN** 该待办的视觉状态与筛选结果同步变化

#### 场景：删除待办成功
- **WHEN** 用户删除某条待办并确认（如有确认流程）
- **THEN** 该待办从列表中移除

### 需求：筛选视图
系统 SHALL 提供“全部/未完成/已完成”三个筛选视图，并保持筛选状态与列表一致。

#### 场景：切换筛选视图
- **WHEN** 用户从“全部”切换到“未完成”
- **THEN** 仅展示未完成待办，且计数与空状态提示正确

### 需求：本地持久化
系统 SHALL 将待办数据持久化到浏览器本地存储，并在刷新后恢复。

#### 场景：刷新后恢复
- **WHEN** 用户刷新页面
- **THEN** 待办列表与筛选状态按上次保存的内容恢复

### 需求：基础可用性与响应式
系统 SHALL 在桌面与移动端可用，并提供基础键盘操作支持与可读的视觉层级。

#### 场景：键盘提交
- **WHEN** 用户在输入框按 Enter
- **THEN** 触发创建待办（若输入有效），并将焦点合理回到输入区域
