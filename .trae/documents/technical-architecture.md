# 技术架构：极简在线二维码生成工具

## 1. 架构总览
产品为纯前端静态站点，无后端依赖；二维码在浏览器端本地生成并渲染为 PNG 图片，用户可直接右键保存。

**关键原则**
- 本地生成：用户输入不离开浏览器
- 静态部署：可部署到任意静态托管（对象存储、CDN、GitHub Pages 等）
- 低依赖：避免复杂工程，优先可直接打开的静态资源方案

## 2. 技术选型（MVP 推荐）

### 2.1 运行时
- 纯 HTML/CSS/JavaScript（无框架）
- 单页应用（SPA 形态但不引入路由）

### 2.2 二维码生成库
优先选择成熟、体积小、可离线使用的库（以下二选一即可）：
- `qrcode`（常见 npm 包，亦有可用的 UMD 构建，便于 CDN 引入）
- `qrcode-generator`（纯 JS，适合生成 Canvas/IMG 数据）

选型标准：
- 支持将文本（UTF-8）编码为二维码
- 支持导出 Canvas 或 data URL（PNG）
- 支持纠错等级与边距设置

### 2.3 渲染策略
- 使用 `<canvas>` 生成，再转成 PNG data URL，赋值给 `<img src="...">`
- 页面最终展示 `<img>`，确保右键“另存为图片”可用

## 3. 页面结构与组件划分
不引入组件框架，按模块拆分 JS：
- `ui`：绑定输入框、清空按钮（如有）、状态提示区域
- `generator`：二维码生成逻辑（接收文本、参数，输出 PNG data URL）
- `utils`：debounce、字符串处理、错误归一化

DOM 区块（概念）：
- Header（可选，仅标题/一句话说明）
- InputArea（textarea）
- OutputArea（img + 轻量提示）
- Footer（可选，隐私说明一行）

## 4. 核心流程

### 4.1 输入到生成（debounce）
1. 用户输入/粘贴文本
2. 前端监听 `input` 事件
3. 通过 debounce（1s）合并高频输入
4. 输入为空：
   - 清空二维码显示，回到空态
5. 输入非空：
   - 调用 `generateQrPngDataUrl(text, options)`
   - 更新 `<img>` 的 `src`

### 4.2 生成参数（建议默认值）
- 尺寸：桌面默认 300px，移动端可 240~280px，自适应容器
- 纠错等级：默认 `M` 或 `Q`（优先可扫性）
- 边距：保留 quiet zone（例如 4 模块）
- 颜色：默认黑白（对比度最高）

## 5. 响应式与样式策略
- CSS 使用自定义变量统一间距、字体、边框
- 布局：
  - ≥ 900px：左右两列（输入与二维码并排）
  - < 900px：上下布局（二维码在下）
- 输入框：
  - 最小高度足够粘贴长链接
  - 聚焦态明确
- 二维码：
  - 固定容器避免布局跳动
  - 图片使用 `image-rendering` 的兼容性需谨慎，核心依赖足够像素尺寸

## 6. 性能策略
- 生成仅在输入稳定后触发，避免每次按键都重绘
- 仅在内容变化时更新输出（可对比上一份文本）
- 图片 data URL 大小与二维码像素相关，默认尺寸适中

## 7. 安全与隐私
- 不引入任何会上传输入内容的服务
- 不把输入内容写入 URL 查询参数（避免意外泄露到浏览器历史/分享）
- 不使用 `innerHTML` 渲染用户输入；所有用户输入仅作为字符串传入二维码生成库
- 如未来接入统计：
  - 默认关闭
  - 严禁采集原始输入内容

## 8. 错误处理与可观测性（MVP）
- 错误分类：
  - 输入为空
  - 输入过长导致生成失败/扫码困难
  - 库异常（极少数）
- UI 展示：
  - 输出区显示一行简洁提示
  - 不弹窗，不跳转

## 9. 部署与运维
- 静态文件部署：
  - `index.html`
  - `styles.css`
  - `app.js`
  -（可选）`vendor/qrcode.min.js` 或 CDN 引入
- 支持无构建部署；如未来需要构建：
  - 采用 Vite 以获得更好的缓存与资源管理，但 MVP 可先不引入

## 10. 测试与验收建议
- 手工测试集：
  - 短 URL、长 URL（含参数）
  - 中文文本、英文文本、带换行文本
  - 1KB 以上文本（观察性能与可扫性提示）
  - 移动端/桌面端布局
- 扫码测试：
  - iOS/Android 系统相机与常见扫码应用
